# PRD: AI·채팅 백엔드

## 1. 배경

웹 기반 AI 챗봇 서비스에서 로그인한 사용자가 질문하고, 이전 대화의 맥락을 반영한 AI 답변을 받을 수 있어야 한다. 질문과 답변은 DB에 저장해 사용자 기준으로 조회·추적할 수 있어야 하며, AI 호출 실패나 타임아웃이 발생해도 오류를 안내하고 서비스를 계속 제공해야 한다.

백엔드는 관리자, 유저, AI·채팅 담당으로 나누어 구현한다. 이 문서는 AI·채팅 담당 범위의 구현 전 초안이다. 인증은 유저 담당자의 기능을 사용하고, 저장한 대화 데이터는 관리자 담당자가 조회 기능에 활용할 수 있도록 구조를 공유한다.

API 요청·응답 계약은 [AI·채팅 API 명세](AI-CHAT-API.md)를 기준으로 한다. 두 문서가 충돌하면 API 명세서를 우선하고, 충돌하지 않는 내부 처리 규칙은 이 PRD를 적용한다. 이 문서의 채팅방은 API 명세서의 세션과 같은 의미다.

## 2. 목표

- 로그인한 사용자가 질문하고 AI 답변을 받을 수 있다.
- 같은 채팅방의 이전 대화를 활용해 문맥을 유지한다.
- 사용자별 질문·응답·시각을 DB에 저장하고 본인 대화를 조회할 수 있다.
- 입력 오류, AI 실패·타임아웃, DB 오류를 처리하고 원인을 로그로 추적할 수 있다.
- 프론트엔드 및 다른 백엔드 담당자가 연동할 수 있는 API와 데이터 구조를 정의한다.

채팅방 단위 대화, 일반 JSON 응답, 최근 5개 질문·응답 활용, 질문 최대 2,000자, AI 호출 타임아웃 30초는 이 초안의 제안이며 팀 협의로 조정할 수 있다.

## 3. 사용자 스토리

### 질문과 답변

- As a 로그인한 사용자,
- I want 채팅방에서 질문하고 이전 대화를 반영한 AI 답변을 받고 싶다.
- So that 대화를 이어가며 필요한 정보를 얻을 수 있다.

### 대화 기록 조회

- As a 로그인한 사용자,
- I want 내 채팅방과 이전 질문·답변을 조회하고 싶다.
- So that 이전에 나눈 대화를 다시 확인할 수 있다.

### 오류 안내

- As a 질문을 전송한 사용자,
- I want 응답 생성에 실패하면 오류 안내를 받고 싶다.
- So that 처리 결과를 이해하고 다시 시도할 수 있다.

## 4. 스코프

### 포함

- 채팅방 생성 및 본인 채팅방 목록 조회
- 질문 전송 및 AI 답변 반환
- 채팅방별 문맥 유지
- 질문·답변·처리 상태 저장 및 본인 대화 기록 조회
- 인증 연동, 채팅방 소유권 검사, 입력 검증
- AI 실패·타임아웃 및 DB 오류 처리
- 요청·AI 호출·DB 저장 이벤트 로그
- API 명세, DB 구조 및 환경변수 설정 문서화

### 제외

- 채팅방 목록 및 대화 기록 페이지네이션
- 회원가입·로그인 및 관리자 API 구현
- 채팅방 이름 변경·삭제, 메시지 수정·삭제
- 스트리밍 응답, 답변 재생성, 자동 재전송
- 파일·이미지·음성 입력 및 외부 문서 검색
- 모델 선택 UI, 결제, 이용량 통계

## 5. 기능 요구사항

- 사용자는 로그인한 상태에서만 채팅 API를 사용할 수 있다.
- 사용자는 본인의 채팅방만 생성·조회하고 질문을 전송할 수 있다.
- 시스템은 인증 정보에서 사용자 식별자를 가져오며, 요청 본문으로 사용자 식별자를 받지 않는다.
- 시스템은 HTTP 요청마다 서버에서 UUID4 형식의 `request_id`를 생성하고 해당 요청의 모든 처리 로그에서 같은 값을 사용한다.
- 시스템은 질문의 앞뒤 공백을 제거하고, 빈 입력 또는 확정된 길이 상한을 초과하는 입력을 거절한다. 이 경우 AI 호출과 대화 기록 생성을 수행하지 않는다. 현재 제안은 1~2,000자이며, API 명세서에 미정으로 표시된 길이 상한은 구현 전에 확정한다.
- 시스템은 AI 호출 전에 질문을 `pending` 상태로 저장하고, 해당 질문 요청의 `request_id`를 대화 기록의 기본키로 사용한다. 답변 저장과 완료·실패 상태 갱신도 같은 `request_id`로 수행한다.
- 시스템은 같은 채팅방의 성공한 최근 5개 질문·응답을 시간순으로 구성하고 현재 질문을 마지막에 추가한다. 다른 사용자·채팅방의 기록과 실패·처리 중 기록은 제외한다.
- AI 입력 한도를 초과하는 경우 가장 오래된 질문·응답 쌍부터 제외하고 현재 질문은 유지한다.
- 시스템은 서버에서 AI API를 호출하고 완성된 답변을 일반 JSON으로 반환한다.
- 시스템은 답변과 `completed` 상태를 저장한 뒤 성공 응답을 반환한다.
- AI 실패·타임아웃이 발생한 경우 질문을 유지하고 `failed` 상태와 오류 코드를 저장한다. 답변은 `null`로 두고 사용자에게 오류를 안내한다.
- 질문 저장에 실패한 경우 AI를 호출하지 않는다. 답변 저장에 실패한 경우 성공 응답을 반환하지 않는다.
- DB 오류로 실패 상태까지 저장할 수 없는 경우 서버 로그에 원인을 남기고 저장 오류를 반환한다.
- 같은 채팅방에 처리 중인 질문이 있는 경우 새 질문을 `409`로 거절한다. 동시에 들어온 요청에서도 서버가 하나만 승인해야 한다.
- 사용자는 본인 대화 기록의 질문·답변·상태·시각을 조회할 수 있다.
- 시스템은 요청 수신, AI 호출 시작, AI 응답 수신 또는 실패, DB 저장 성공·실패를 요청 식별자로 연결해 로그에 남긴다.

## 6. API 명세

모든 API에 유저 담당자가 제공하는 인증 의존성을 적용한다. 인증 전달 방식과 사용자 ID 자료형은 유저 담당자의 계약에 맞춘다. 아래 API 및 오류 포맷은 API 명세서를 따른다. 채팅방 식별자 `chat_id`는 UUID이며, UUID 형식이 아닌 경로 매개변수는 `422 INVALID_INPUT`으로 처리한다.

### POST /api/v1/chats

Request:

- 요청 본문 없음

Response:

```json
{
  "chat_id": "e6100748-b7f0-48e6-a264-7c20a748cf93",
  "created_at": "2026-09-30T03:00:00Z"
}
```

Status Codes:

- 201: 채팅방 생성 성공
- 401: 인증 실패
- 500: DB 저장 실패

### GET /api/v1/chats

Request:

- 요청 본문 없음
- 로그인한 사용자의 전체 채팅방 목록 조회

Response:

```json
{
  "items": [
    {
      "chat_id": "e6100748-b7f0-48e6-a264-7c20a748cf93",
      "created_at": "2026-09-30T03:00:00Z"
    }
  ]
}
```

Status Codes:

- 200: 본인 채팅방 목록 조회 성공
- 401: 인증 실패
- 500: DB 조회 실패

### POST /api/v1/chats/{chat_id}/messages

Request:

```json
{
  "question": "FastAPI가 무엇인지 설명해줘."
}
```

Response:

```json
{
  "request_id": "16fd2706-8baf-433b-82eb-8c7fada847da",
  "chat_id": "e6100748-b7f0-48e6-a264-7c20a748cf93",
  "question": "FastAPI가 무엇인지 설명해줘.",
  "answer": "FastAPI는 Python으로 웹 API를 만드는 프레임워크입니다.",
  "status": "completed",
  "error_code": null,
  "created_at": "2026-09-30T03:00:00Z",
  "finished_at": "2026-09-30T03:00:02Z"
}
```

Status Codes:

- 201: 질문·답변 저장 및 반환 성공
- 401: 인증 실패
- 404: 채팅방이 없거나 본인 소유가 아님
- 409: 해당 채팅방의 이전 질문이 처리 중
- 422: 질문 입력 또는 UUID 형식 오류
- 500: DB 조회·저장 실패
- 502: AI 연결·외부 서비스 실패 또는 유효한 답변 없음
- 503: AI 키·모델 등 서버 설정 오류
- 504: AI 호출 타임아웃

### GET /api/v1/chats/{chat_id}

Request:

- 요청 본문 없음
- 본인 채팅방 정보와 전체 대화 기록을 함께 조회

Response:

```json
{
  "chat_id": "e6100748-b7f0-48e6-a264-7c20a748cf93",
  "created_at": "2026-09-30T03:00:00Z",
  "messages": [
    {
      "request_id": "16fd2706-8baf-433b-82eb-8c7fada847da",
      "chat_id": "e6100748-b7f0-48e6-a264-7c20a748cf93",
      "question": "FastAPI가 무엇인지 설명해줘.",
      "answer": "FastAPI는 Python으로 웹 API를 만드는 프레임워크입니다.",
      "status": "completed",
      "error_code": null,
      "created_at": "2026-09-30T03:00:00Z",
      "finished_at": "2026-09-30T03:00:02Z"
    }
  ]
}
```

Status Codes:

- 200: 본인 채팅방 정보 및 전체 대화 기록 조회 성공
- 401: 인증 실패
- 404: 채팅방이 없거나 본인 소유가 아님
- 422: UUID 형식 오류
- 500: DB 조회 실패

### 공통 조회·오류 규칙

- 채팅방 목록과 상세의 대화 기록은 페이지 조회 없이 전체를 반환한다. `limit`, `offset`, `has_more` 필드는 사용하지 않는다.
- 채팅방 목록은 `created_at`·`chat_id` 내림차순, 대화 기록은 `created_at`·`request_id` 오름차순으로 조회한다. UUID 자체는 생성 순서를 나타내지 않으므로 시각을 우선 정렬 기준으로 사용한다.
- 채팅방이 없으면 목록 응답은 `{"items": []}`를 반환한다. 본인 채팅방에 대화 기록이 없으면 상세 응답의 `messages`는 빈 배열이다.
- 채팅방 상세의 `messages`에는 처리 중·성공·실패 기록을 모두 포함한다.
- `messages`의 항목 하나는 질문 1개와 답변 최대 1개로 구성된 대화 기록이다.
- 대화 기록의 모든 필드를 응답에 포함한다. `pending`의 `answer`, `error_code`, `finished_at`은 `null`이며, `completed`의 `error_code`는 `null`이다. `failed`의 `answer`는 `null`이고 `error_code`와 `finished_at`은 실패 코드와 실패 시각이다.
- 대화 기록의 `request_id`는 최초 질문 요청의 값으로 유지한다. 기록 조회 요청에는 새로운 `request_id`를 생성하되, 응답의 대화 기록에는 저장된 최초 질문의 `request_id`를 반환한다.
- 시각은 UTC 기준 ISO 8601 형식으로 반환한다.
- 오류 응답은 다음 형식을 사용한다. `request_id`로 해당 요청의 서버 로그를 추적하고, 질문이 저장된 경우 같은 값으로 대화 기록도 식별한다. 입력 검증에서 거절되거나 질문 저장에 실패하면 대화 기록이 없을 수 있다.

```json
{
  "error": {
    "code": "AI_TIMEOUT",
    "message": "응답이 지연되고 있습니다. 잠시 후 다시 시도해 주세요.",
    "request_id": "16fd2706-8baf-433b-82eb-8c7fada847da"
  }
}
```

오류 코드는 상황에 따라 `UNAUTHORIZED`, `CHAT_NOT_FOUND`, `CHAT_BUSY`, `INVALID_INPUT`, `DB_ERROR`, `AI_UNAVAILABLE`, `AI_CONFIGURATION_ERROR`, `AI_TIMEOUT`을 사용한다.

## 7. 기술 요구사항

- FastAPI를 사용한다.
- API는 `/api/v1` 아래에 구성한다.
- 비즈니스 로직과 AI 호출·문맥 구성·소유권 검증은 Service 계층에서 처리한다.
- DB 접근은 Repository 계층에서 처리한다.
- 요청/응답 모델은 Pydantic으로 정의한다.
- SQLAlchemy 비동기 세션과 SQLite를 사용한다.
- 서버의 OpenAI SDK를 사용해 AI API를 호출한다.
- `OPENAI_API_KEY`, `OPENAI_MODEL`은 환경변수로 관리하고, `AI_TIMEOUT_SECONDS`를 추가해 기본 30초의 타임아웃을 설정한다.
- `.env`는 Git에서 제외하고 `.env.example`과 실행 문서에 설정 방법을 제공한다.
- DB 트랜잭션은 AI 응답을 기다리는 동안 열어두지 않는다. 질문 저장과 완료·실패 갱신을 각각 처리한다.
- AI 호출을 자동 재시도하지 않는다.
- 서버 로그에는 `request_id`, 사용자·채팅방 식별자, 처리 결과와 오류 코드를 남긴다. AI 처리 시간도 기록한다.
- API 키·인증 정보·질문·답변 원문은 일반 서버 로그에 출력하지 않는다. 외부 API 원본 오류나 스택 트레이스는 사용자에게 반환하지 않는다.
- 사용자 모델·인증 의존성은 유저 담당자와, 관리자 조회에 필요한 데이터 구조는 관리자 담당자와 합의한다.
- 서버 중단 후 남은 `pending` 기록의 정리와 계정 삭제 시 대화 데이터 처리 정책은 구현 전에 팀과 합의한다.

DB 구조는 다음을 기준으로 한다. 사용자 외래키의 대상과 자료형은 유저 담당자의 모델에 맞춘다.

| 테이블 | 필드 | 용도 |
| --- | --- | --- |
| `chats` | `chat_id`, `user_id`, `created_at` | 채팅방 및 소유자 관리 |
| `chat_logs` | `request_id`, `chat_id`, `question`, `answer`, `status`, `error_code`, `model`, `created_at`, `finished_at` | 질문·응답 및 처리 상태 저장 |

- 사용자 1명은 여러 채팅방을, 채팅방 1개는 여러 대화 기록을 가진다.
- `chats.chat_id`는 UUID 기본키이며, `chat_logs.chat_id`는 해당 채팅방을 참조한다.
- `chat_logs.request_id`는 UUID4 기본키이며, 질문 요청 하나당 대화 기록 하나를 생성한다. 별도 대화 기록 ID는 두지 않는다.
- 사용자 기준 조회는 `chat_logs`와 `chats`를 연결하고 `chats.user_id`로 필터링한다.
- `status`는 `pending`, `completed`, `failed` 중 하나다.
- 처리 중·실패 상태의 `answer`는 `null`이며, 처리 중의 `finished_at`은 `null`이다.
- `user_id` 및 채팅방별 기록 조회에 필요한 인덱스를 구성한다.

### 구현 전 확인할 계약·정책

- 사용자 모델·테이블과 기본키 자료형, 인증 의존성의 import 경로·반환값, 인증 전달 방식은 유저 담당자의 계약 확인 후 연결한다. 현재 코드에는 사용자 모델과 인증 의존성이 없으므로 임의로 정의하지 않는다.
- 서버 중단 후 남은 `pending` 기록의 정리 시점·조건·실패 코드는 팀 합의 후 정한다. 처리 중인 정상 요청을 정리 대상으로 판단하지 않도록 기준이 필요하다.
- 계정 삭제 시 채팅방·대화 기록을 삭제할지 유지할지, 외래키의 삭제 동작은 팀 합의 후 정한다.
- AI 입력 한도에 맞춘 문맥 축소를 위해 입력 토큰 예산과 토큰 계산 방식을 정한다. 현재 질문을 유지한 상태로도 한도를 넘는 경우의 처리 규칙은 PRD에 추가할 필요가 있다.
- 질문 길이 상한은 API 명세서의 미정 사항이며, 현재 제안인 2,000자를 확정할지 확인한다.

## 8. 완료 조건

- [ ] 로그인한 사용자만 채팅 API를 사용할 수 있다.
- [ ] 본인 채팅방 생성·목록 조회·질문 전송·대화 기록 조회가 동작한다.
- [ ] 실제 AI API 호출로 답변을 받고 질문·답변이 DB에 저장된다.
- [ ] 같은 채팅방의 최근 대화가 AI 입력에 포함되어 문맥이 유지된다.
- [ ] 타인 채팅방에 접근할 수 없고 다른 사용자·채팅방의 기록이 AI 입력에 포함되지 않는다.
- [ ] 빈 입력·공백 입력·확정된 길이 상한 초과 입력에서 AI 호출과 대화 기록 생성이 발생하지 않는다.
- [ ] AI 실패·타임아웃에서 오류 안내, 질문 유지 및 실패 상태 기록을 확인한다.
- [ ] DB 저장 실패 시 성공 응답을 반환하지 않고 원인을 로그에 남긴다.
- [ ] 같은 채팅방의 동시 질문 중 하나만 승인되고 나머지는 `409`를 받는다.
- [ ] UUID형 `chat_id`를 사용하는 채팅방 목록과 상세 조회에서 전체 기록 및 정렬 순서를 확인하고, 서버 재시작 후에도 기록이 남는다.
- [ ] 요청·AI 호출·DB 저장 성공·실패 로그를 요청 식별자로 추적할 수 있다.
- [ ] 질문 요청의 UUID4 `request_id`가 대화 기록의 기본키로 사용되고 답변·상태 갱신 및 재조회 후에도 유지된다.
- [ ] API 요청·응답, DB 구조, 환경변수·실행 방법, 개인 작업 요약을 문서화한다.
- [ ] 담당 기능의 PR 기반 Merge 기록과 유의미한 개인 커밋 10회 이상을 남긴다.
- [ ] 배포 URL에서 로그인 → 질문 → 답변 확인 → 기록 재조회 흐름을 검증한다.

실제 AI API·배포 검증과 대체 클라이언트로 재현한 실패·타임아웃 검증은 구분해 기록한다.
