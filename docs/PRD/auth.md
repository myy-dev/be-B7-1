# 회원 인증

회원가입·로그인·로그아웃·내 정보 조회를 제공하고, 인증된 회원만 채팅 API를 사용하도록 합니다.

## API 계약

경로·요청·응답·입력 제한은 [Swagger](https://be-b7-1-development.up.railway.app/docs)의 `auth` 항목에서 확인합니다. 공통 오류 응답은 [운영 안내](../OPERATIONS.md#공통-오류-처리)를 참고합니다.

| 기능 | 처리 결과 |
| --- | --- |
| 회원가입 | 검증·아이디 중복 검사 → Argon2 해싱 → 일반 회원 저장. 201 |
| 로그인 | 아이디·비밀번호 확인 → 마지막 로그인 시각 갱신·JWT 발급. 200 |
| 로그아웃 | 현재 토큰 폐기. 본문 없는 204 |
| 내 정보 | 인증된 회원의 DB 정보와 현재 역할 조회. 200 |

## 회원가입과 로그인

- 아이디는 소문자로 저장하고 대소문자를 구분하지 않고 중복 검사합니다. 동시 가입 충돌도 `409 USERNAME_TAKEN`으로 처리합니다.
- 회원가입의 `username`·`password`·`name`은 필수이며 `role` 등 추가 필드는 거절합니다. 서버가 역할을 `user`로 지정하고 비밀번호 확인은 프론트에서 처리합니다.
- 가입 비밀번호는 공백·한글을 허용하지 않고 ASCII 영문·숫자·특수문자를 모두 포함해야 합니다. 이름은 앞뒤 공백을 제거합니다. 비밀번호는 원문 그대로 Argon2 해시로 저장합니다. 비밀번호와 해시는 응답에 포함하지 않습니다.
- 가입 완료 후 프론트는 로그인 화면으로 이동합니다. 가입 API는 토큰을 발급하지 않습니다.
- 로그인에서 비밀번호 공백은 그대로 비교합니다. 없는 아이디와 잘못된 비밀번호는 같은 `401 INVALID_CREDENTIALS`를 반환합니다.

## 인증 상태와 권한

- 보호 API는 `Authorization: Bearer <access_token>`을 사용합니다. Swagger의 Authorize에도 로그인으로 받은 토큰을 입력합니다.
- HS256 서명, 필수 `sub`·`iat`·`exp`, 토큰 폐기 여부와 회원 존재를 확인합니다. 토큰 누락·만료·위조·폐기 또는 삭제된 회원은 `401 UNAUTHORIZED`입니다.
- 관리자 API는 DB `role`을 추가 확인하며 일반 회원은 `403 FORBIDDEN`입니다. 역할 변경은 다음 요청부터 반영됩니다.
- refresh token은 제공하지 않습니다. 액세스 토큰 만료 후 다시 로그인합니다. 기본 유효 시간은 30분입니다.
- 프론트의 토큰 보관·401 처리와 서버 접근 제어는 [인증과 접근 제어](../ARCHITECTURE.md#인증과-데이터-소유권)를 참고합니다.

## 로그아웃과 폐기 기록

현재 토큰의 SHA-256 해시와 만료 시각을 DB에 저장하므로 재시작 후에도 재사용할 수 없습니다. 다른 로그인에서 발급한 토큰은 유지되고 다시 로그인하면 새 토큰을 받습니다. 이미 폐기되거나 만료된 토큰으로 로그아웃하면 401입니다.

프론트는 성공 응답 후 저장한 토큰을 삭제합니다. 폐기 기록 테이블은 앱 시작 시 생성하고, 만료된 폐기 기록은 이후 로그아웃 시 정리합니다. 저장 구조는 [DB 문서](../DATABASE.md)를 참고합니다.

## 설정과 확인

JWT 키의 생성·최소 길이, 만료 시간 설정과 실행 방법은 [운영 환경 변수](../OPERATIONS.md#환경-변수)와 [로컬 실행](../GETTING_STARTED.md#로컬-실행)을 따릅니다. 잘못된 JWT 설정은 서버 시작을 막습니다.

`uv run pytest`는 임시 SQLite DB로 검증하며 개발 DB를 수정하지 않습니다. 실제 서비스의 확인 절차는 [운영 검증](../OPERATIONS.md#운영-검증)을 참고합니다.
