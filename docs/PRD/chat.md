# AI 채팅

로그인한 사용자가 같은 채팅방에서 문맥을 이어 질문하고, 저장된 질문·답변·시각을 본인 기준으로 조회하는 기능입니다. 요청·응답은 [Swagger](https://be-b7-1-development.up.railway.app/docs)에서 확인합니다. 채팅방과 세션은 같은 의미입니다.

## 기능 범위

회원 인증을 거쳐 채팅방 생성·조회·논리 삭제, 질문 전송, 문맥 구성, 기록 저장, 소유권·입력 검증을 처리합니다. AI 예외·재시도·타임아웃과 이벤트 로그를 관리하며, 저장된 기록은 관리자도 조회할 수 있습니다.

### 제외 범위

- 회원가입·로그인·관리자 API 자체 구현
- 채팅 목록·기록 페이지네이션, 이름 변경·복구·물리 삭제, 메시지 수정·삭제
- 스트리밍·답변 재생성·프론트 질문 자동 재전송
- 파일·이미지·음성 입력·외부 문서 검색·모델 선택 UI·결제·이용량 통계

## 기능 요구사항

| 영역 | 규칙과 상세 문서 |
| --- | --- |
| 인증·소유권 | 로그인한 회원 ID를 인증 정보에서 얻고 본인 미삭제 채팅방만 조회·질문·삭제. [접근 제어](../ARCHITECTURE.md#인증과-데이터-소유권) |
| 질문 검증 | 앞뒤 공백 제거 후 1~1,000 Unicode 코드 포인트. 거절 시 기록·AI 호출 없음. [입력 처리 정책](#입력-처리-정책) |
| 식별·저장 | UUID4 요청 ID를 로그와 대화 기본키로 사용. pending 질문 저장 → AI 호출 → 같은 기록을 completed 또는 failed로 갱신. [DB](../DATABASE.md) |
| 문맥 | 같은 방의 최근 completed 질문·답변 최대 5쌍을 시간순으로 전달하고 현재 질문 추가. 다른 방·실패·처리 중 기록 제외. [문맥 전략](../ARCHITECTURE.md#최근-대화-5개-문맥-전략) |
| 성공·실패 | 완성된 답변 저장 후 201 JSON. AI 실패는 질문 유지·failed·오류 코드 저장. DB 실패는 성공 응답 금지. [운영 오류 대응](../OPERATIONS.md#ai-재시도와-타임아웃) |
| 재시도 | 같은 질문·문맥·요청 ID와 기록 한 건 유지. 기본 최대 5회, 호출·대기 포함 전체 30초. [재시도 정책](../OPERATIONS.md#ai-재시도와-타임아웃) |
| 조회 | 사용자별 전체 기록과 처리 상태·시각 반환. [조회 정책](#대화-조회와-삭제-정책) |
| 삭제 | UTC deleted_at으로 논리 삭제하고 DB 원본 보존. AI 생성 중에도 허용하며 기존 요청은 결과 저장·응답 계속. [삭제 정책](#대화-조회와-삭제-정책) |
| 로그 | 요청 수신·AI 시작과 최종 결과·DB 저장 성공과 실패를 같은 요청 ID로 연결. [로그 계약](system-logs.md) |

타임아웃·재시도 횟수는 환경 변수로 조정합니다.

## 입력 처리 정책

질문은 앞뒤 공백을 제거한 뒤 Python `len()`의 Unicode 코드 포인트 수로 검증하고 저장합니다. 내부 공백·줄바꿈도 포함하며 별도 Unicode 정규화는 하지 않으므로 조합 이모지는 여러 글자로 셀 수 있습니다. 거절된 입력에는 기록 생성·AI 호출을 하지 않고 원문·내부 검증 상세를 응답에 넣지 않습니다. 필드 형식과 제한은 Swagger의 요청 스키마에서 확인합니다.

1,000자 초과는 `422 INVALID_INPUT`과 "질문은 1,000자를 초과할 수 없습니다."를 반환합니다. 다른 입력 오류의 안내는 "입력값을 확인해 주세요."입니다.

## 대화 조회와 삭제 정책

- 사용자 목록은 미삭제 채팅방 전체를 생성 시각·채팅방 ID 내림차순으로 반환합니다. 대화는 생성 시각·요청 ID 오름차순이며 처리 중·성공·실패 기록을 모두 포함합니다. 현재 페이지네이션은 없습니다.
- 목록이나 기록이 없으면 빈 배열을 반환합니다. 조회 요청에는 새 요청 ID를 부여하지만 저장된 대화 기록의 ID는 최초 질문 요청 값으로 유지합니다. 시각은 UTC로 처리합니다.
- 논리 삭제는 `deleted_at`만 기록하고 채팅방·대화 행과 외래키는 유지합니다. 사용자 목록에서 제외하고 상세 조회·새 질문·재삭제는 거절합니다. 내부 삭제 필드를 응답에 추가하지 않습니다.
- AI 생성 중이거나 pending 기록이 남아 있어도 삭제할 수 있습니다. 삭제가 AI 호출을 취소하거나 채팅방을 복구하지 않습니다.
- 삭제 전 소유권·삭제 여부 검사를 통과한 질문은 기존 기록에 완료·실패 결과를 저장하고 원래 요청에 응답합니다. 기존 성공·오류 처리 규칙은 유지합니다.
- 프론트는 삭제된 방의 늦은 답변을 화면에 표시하거나 방을 목록에 다시 추가하지 않습니다.

## 기술 구성

계층·AI 클라이언트 수명주기·처리 흐름은 [아키텍처](../ARCHITECTURE.md), 테이블·관계·상태 조합은 [DB](../DATABASE.md), 설정과 AI 오류 대응은 [운영](../OPERATIONS.md)을 참고합니다.

## 미구현 요구사항과 미확정 정책

- **동시 질문 차단 미구현:** 같은 방의 진행 중 질문이 있으면 새 요청을 `409 CHAT_BUSY`로 거절하고 동시 요청 중 하나만 승인하는 요구사항이 남아 있습니다. 현재 잠금·차단·반환 경로는 없습니다.
- **토큰 예산에 따른 문맥 축약 미구현:** 입력 한도를 넘으면 오래된 쌍부터 제외하고 현재 질문은 유지한다는 요구사항이 남아 있습니다. 예산·계산 방식과 현재 질문만으로 한도를 넘는 경우의 처리는 미확정입니다.
- 중단 후 남은 `pending` 자동 복구는 미구현입니다. 정상 진행 중 요청과 구분할 정리 시점·조건·실패 코드를 합의해야 합니다.
- 계정 삭제 시 대화 보관·삭제와 외래키 동작은 미확정입니다. 현재 자동 삭제를 설정하지 않고 기본 참조 무결성을 유지합니다.

## 기능 확인

실제 AI 호출·배포 환경 검증과 대체 클라이언트로 재현한 실패·타임아웃 검증을 구분합니다.

- 배포 서비스에서 로그인 → 채팅방 생성 → 실제 AI 질문·답변 → 기록 재조회가 이어지는지 확인합니다.
- 비로그인 요청과 타인 채팅방 접근을 거절하고, 다른 방의 기록을 문맥에 포함하지 않는지 확인합니다.
- 질문 길이 경계·공백·Unicode 처리와 오류 안내를 확인합니다. 검증 실패 시 기록·AI 호출이 없어야 합니다.
- 문맥에 최근 완료 대화만 오래된 순으로 포함되는지 확인합니다.
- 삭제 후 원본 보존·사용자 조회 차단, AI 생성 중 삭제 후 기존 요청의 결과 저장을 확인합니다.
- [AI 재시도·타임아웃 정책](../OPERATIONS.md#ai-재시도와-타임아웃)의 횟수·대기·오류별 처리를 검증하고, 질문 기록 한 건과 최종 응답·저장 상태가 일치하는지 확인합니다.
- DB 실패 시 성공 응답이 없고, 최초 질문 ID·전체 기록·정렬 순서가 재조회와 재시작 후에도 유지되는지 확인합니다. [DB 확인 절차](../DATABASE.md#저장된-질문과-답변-확인) 참고.
- 요청 ID별 이벤트 로그와 실패 후 다음 요청 처리를 확인합니다. [운영 검증](../OPERATIONS.md#운영-검증) 참고.
